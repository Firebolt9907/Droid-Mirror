# Phone blackout overlay

The Android app's Optional features and recovery dialog offers **Black out phone with mirroring message (optional)**. The `ready.blackoutOverlay` preference defaults to false. Settings are sampled once per new session, so toggling this option never replaces components during an active mirror. The existing `panelOff` preference is preserved and resumes when the overlay option is disabled.

On Android 12+, the Shizuku display guard owns a secure SurfaceControl/BLAST layer above the default display. `setSkipScreenshot(true)` excludes the entire layer from capture rather than substituting black pixels. The layer is hidden until secure and capture-exclusion flags have been applied. It draws an AOD-style interface on pure black: a large bold centered clock in the upper area, an outlined “Phone in Use” activity card near the bottom, and a small centered battery percentage at the bottom. The card closely follows the reference phone-and-pointer icon and title/body hierarchy:

> Phone in Use
>
> This phone is being used from “[Mac name]”.

The activity card height follows its wrapped body text with 26 atlas pixels of bottom padding, and the phone-and-pointer glyph stays vertically centered. The date uses 56-pixel type with extra space above it; the clock stays at its existing position. The compositor includes the date below the clock and the complete relocated card; the card outline sits 35 atlas pixels above the battery region in both orientations. A charging bolt accompanies the battery percentage when charging or full. The clock uses the phone’s locale and 12/24-hour setting. Battery percentage comes from Android’s battery state. The app checks for changes once per second and sends a fresh atlas only when time or battery changes. Refreshes require the calling app UID and the existing live session owner; they do not acquire or extend a lease. Informational refresh failures retain blackout coverage and retry after 30 seconds. Small discrete position shifts accompany minute updates. Notification icons, weather, music and fingerprint controls are omitted. All content remains dark neutral grey (maximum channel value 90); there is no glow. Startup fades the content in over 240 ms; the activity card rises from below the display and scales from 86% to 100% over the same 420 ms: translation uses cubic ease-in, while scale uses cubic ease-out. The animation starts after the display wakes, never before black coverage is established. Normal stop and power-button interruption fade content out over 200 ms on opaque black. The phone is locked before the exit fade; local interruption wakes behind the black cover so the fade is visible before the lock screen is revealed. Input/capture are stopped before the exit fade. Entrance frames are cancelled before exit or layer destruction; failed or emergency cleanup removes the layer immediately without waiting for animation.

It is created before waking the display or entering a saved PIN. It does not take window focus, intercept Mac input, or change app security flags. The app renders the icon and text to a 900 × 800 PNG atlas before sending it to the shell guard. The guard only draws bitmap pixels: Android 17 shell processes have uninitialized/lazy default fonts, and Canvas.drawText previously triggered a fatal libhwui assertion. The phone display stays on. A square buffer is allocated at the display's longer side in actual display pixels, covering portrait and landscape through rotation without a compositor scale; the watchdog updates component positioning and display stack after size changes. Unsupported compositor APIs fail session startup rather than quietly exposing the phone. Both the older BLAST constructor and the newer constructor plus `update()` path are supported.

Power-button screen-off uses the existing local-use policy: end the session, lock the phone, remove the overlay, and wake the lock screen. Stop, transport/capture failure, app death, heartbeat expiry, recovery and guard shutdown use the same session-end cleanup. SurfaceFlinger also removes process-owned layers when the shell process dies. Authentication, ownership and input sequence handling remain in the existing session/transport path.

Physical touchscreen input is blocked with exclusive Linux evdev grabs (`EVIOCGRAB`) on direct multitouch screen devices. Mice, touchpads, Mac-injected events and the separate hardware power-button device remain available. A separate power-key device must be detected before grabbing. Grabs are scoped to open file descriptors: normal session cleanup closes them, and the kernel releases them even on native crashes or SIGKILL. No global input-device disable state is changed. If discovering or grabbing a screen fails, startup ends and already acquired grabs are closed.

The compositor layer must also be marked trusted with `setTrustedOverlay()` before it is shown. Capture exclusion and lack of an input channel alone do not exempt an opaque layer from Android's input occlusion policy. The current guard version is 64, which replaces the version 61 daemon shipped without this flag when the next session binds.

The display guard daemon version is bumped to 66 to load the new atlas validator, component layout and owner-checked refresh API after an update. The previous 1024-square scaling approach could be overwritten by Surface/BLAST buffer transactions, exposing the right and bottom of the display. Full-size buffers avoid that dependency. Version 55 also refreshed stale daemon code left running after the touchscreen selection fix. **End active mirrors before installing the updated APK**, so APK replacement and Shizuku daemon refresh do not interrupt a live session.

## Validation

- Full-size buffer verified live on the Pixel 8: SurfaceFlinger reports blackout bounds `(0,0)-(2400,2400)` and output visible region `(0,0)-(1080,2400)`, covering the complete physical display. The mirror reaches `STREAM_STARTED`, and Android reports streaming with the blackout overlay. The prior scaling implementation left the original 1024-square footprint visible.

- Build: `cd BluetoothCompanion && ANDROID_HOME="$HOME/Library/Android/sdk" ./gradlew --offline --no-daemon :assembleDebug -x buildPeerTransport` (reuses the existing JNI artifacts).
- Device regression: `bash Native/test-blackout-text-device.sh` renders bitmap messages in a shell process without font initialization; `bash Native/test-touch-block-device.sh` verifies exclusive touchscreen ownership, normal release and SIGKILL release. Both passed on the connected API 37 phone.
- Input policy regression: `bash Native/test-blackout-input-device.sh` briefly shows the overlay and injects DOWN/UP outside mirroring. It requires an awake, unlocked phone; injection acceptance while dozing or on the keyguard is not a valid app-input check. Set `BLACKOUT_TEST_APK` to compare another APK. This checks dispatcher acceptance; also verify clicks and drags reach an ordinary app during a real mirror session.
- Recovery policy: `bash Native/test-display-transitions.sh`.
- A nonvisual API probe on the connected Android API 37 phone confirmed every required compositor method/constructor is available. No overlay was shown and the APK was not installed.
- AOD rendering checks: build `:assembleDebugAndroidTest`, install the debug and test APKs, and run `adb shell am instrument -w app.droidmirror.bluetooth.test/app.droidmirror.bluetooth.BlackoutAppearanceTest`. Checks use actual app fonts, portrait/landscape composition, 12/24-hour samples, live time/battery, long/fallback Mac names, malformed atlas rejection, payload limits, subdued greys, monotonic entrance easing and fully opaque black fade endpoints in both orientations. PNG previews are saved in the app’s files directory.
- Device acceptance still requires a mirror session: verify the phone shows the clock, correct Mac name and live battery on black while Mac video and input work, and phone touches have no effect; rotate both ways; press power and confirm the overlay disappears and the lock screen becomes usable.
- Repeat with normal stop, lost connection, app force-stop, guard death and the Restore phone display action. Confirm overlay removal, capture termination and existing remote-use audit behavior.
- Disable the setting and confirm the previous panel-off choice resumes. Change it during a session and confirm it only affects the following session. Test startup failure on a device without the required hidden APIs.
