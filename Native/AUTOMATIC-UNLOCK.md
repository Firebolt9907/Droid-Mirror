# Optional automatic screen unlock

On Android open **DroidMirror → Optional features and recovery → Automatic unlock / saved PIN**.
Confirm the current device credential, enter and confirm the numeric screen-lock
PIN (4–16 digits), then save. This is separate from the Mac Bluetooth pairing code.
The same screen replaces or removes the saved PIN; it never reveals the old value.
Saving enables automatic entry for future authenticated Bluetooth/hybrid sessions
and authorized ADB sessions. The last foreground app remains selected; Android
shows home if there is no app to resume. No Home key is injected.

The app stores only AES-256-GCM ciphertext and its random IV in private preferences.
The non-exportable key is generated by Android Keystore. App backups are disabled.
The editor requires device credential confirmation, blocks screenshots/recents
previews, disables autofill and field-state saving, and clears fields on exit.
The key intentionally permits use while locked, so a trusted paired Mac or an
authorized ADB computer can unlock the phone without local confirmation. Hardware
backing depends on the device. Root or a compromised app process can still observe
the decrypted PIN. This feature does not bypass Android credential verification.

A PIN is decrypted only for startup and handed over phone-local Binder to the
privileged input process. Mutable PIN arrays are cleared afterward. There are no
PIN command-line arguments, clipboard transfers, Bluetooth/ADB wire messages to
the computer, or PIN logs. Before handing over a PIN, the app synchronously persists
a 15-second cooldown timestamp. Confirmed keyguard dismissal clears it through a
phone-local callback. A later encoder or transport failure therefore does not pause
a PIN that already unlocked the phone. A failure, crash or interrupted unlock
prevents rapid reconnect attempts with a stale PIN. During the cooldown, normal
mirroring connects without reading or entering the PIN, so manual unlock remains
available. After expiry, only a new user-initiated connection can try the PIN again;
there is no background retry loop. Legacy indefinite pauses automatically expire.
Saving a replacement PIN clears the cooldown. Change the saved value whenever the
phone PIN changes.

Bluetooth startup keeps the existing authenticated transport and ownership checks,
rejects a phone already in use, acquires display recovery before waking, and warms the capture/encoder in parallel with PIN entry. Codec metadata may
reach the Mac decoder immediately, but an output gate drops captured pixel frames
until unlock succeeds. The gate rejects queued pre-unlock timestamps and requests
a fresh keyframe before releasing video. Physical screen-off follows the
existing user preference. ADB uses a DUMP-protected companion service and a one-shot
Binder handshake in parallel with encoder preparation; its PIN entry can be visible on the
physical phone until the client turns the panel off. Both paths open Android's
credential bouncer, clear partial input, enter digits once, submit only if still
locked, and require keyguard dismissal before video begins. Keyguard state is
checked before every key to stop if another unlock occurs. Normal Android unlock
sounds/haptics follow the phone settings. OEM credential screens, lockout timers,
SIM locks, and managed-device restrictions can prevent automatic entry; there is
no claim of universal lock-screen compatibility.

## Verification

Run `bash Native/test-pin-unlock.sh` for leading zeros, validation, already-unlocked
phones, explicit and automatic confirmation, early biometric dismissal, one failed
attempt and bounded timeout. Build the companion with `./gradlew assembleDebug`
and rebuild the bundled scrcpy server for ADB support.

On a test phone, verify save/replace/remove, credential cancellation, rotation and
backgrounding (no retained field values), screenshots blocked, and no plaintext
PIN in preferences/logs. Lock with an app foreground, start Bluetooth and ADB
sessions, and verify the first visible video is that app. Repeat from home, with
screen-off enabled/disabled, with a wrong PIN, after a crash during preparation,
after reboot/first unlock, and after changing the system PIN. A wrong PIN must
fail without exposing its entry frames. The next connection must stream normally
for manual unlock while automatic entry cools down across app restarts. Reconnecting after 15 seconds
can try the PIN again.
The Mac keeps the loading view over transient fully black frames and starts the
entrance animation on content. The loading overlay stays above SDL’s newly created Metal surface during warmup,
preventing empty-drawable flashes. A genuinely black/protected app receives a bounded
1.5-second fallback without the entrance animation.

Before installing an update, end any active mirror session gracefully, then replace
the app/server and reconnect. An independent startup timer reapplies panel-off during Android’s asynchronous wake and PIN injection; it does not extend the recovery deadline. The Shizuku service version is bumped for the new
capture signature; replacing components during an active session is not seamless.
